# 我只在乎你

独立 AstrBot 插件。全天约每 50～70 分钟获得一次自主行动机会，根据当前人格、近期对话和“我会牢牢记住你”记忆，选择聊天、创作、工具行动或沉默。

## 使用

### 长期任务（第一版）

计划页“长期任务”可添加明确目标和完成标准，支持暂停、核对后恢复、取消、移除已结束记录。普通私聊模型可调用 `autonomous_long_task`，当前待办取消工具也能取消长期任务。任务与当前对象绑定，随 state_v1 保存；每个任务独立记录阶段摘要、工具回执、结果和工作区路径。

沿用 AstrBot 工具 Agent，contexts 为空，不带入日常聊天和人格；每轮最多执行配置的模型步骤，继续阶段至少等待90秒，最多12阶段后等待核对。异常进入失败、需要信息进入等待，不无限重试。用户消息优先，中断/重启后运行中任务转等待，由用户核对后恢复。受每日预算、聊天保护期和总暂停限制。明确手动计划优先于长期任务。

工作区为任务专属建议目录，并非操作系统级沙箱；工具仍遵循原有权限。任务禁止自动发消息，完成结果在网页查看；任务记录移除不删除源文件。当前不接 Hermes、不自动写长期记忆，也不保证模型自报完成等于业务验收。外部生成/进程需要原服务取消接口，取消本地任务仅停止后续调度。未结束的其他长期任务等待当前会话下一次调度；不是无限常驻模型推理。

普通私聊可通过 `autonomous_task_control` 查询与取消当前对象的自主任务。请求中提供真实待办ID；模型结合用户当前原话理解“已经好了、不用折腾了”等表达，引用原话并选择取消ID。后端验证会话、当前原话及任务句柄，清除相同任务的计划与断点并保留取消记录；不以单纯口头答应作为取消成功。无关任务保留，第三方已启动进程不在本接口终止范围。是否调用仍依赖模型正确理解和工具启用。

作品去重会在后台为旧条目补正文指纹，比较时仅移除与标题一致的首行及首尾空白，避免本地保存格式与陪伴正文不同而重复展示；同名不同正文仍保留。完结项目会尝试把“项目名·第X章/节/段/回”的已登记文本按编号合订为真实TXT终稿，保留原章、不自动投递。缺章、不同系列或同章不同版本不猜测合并，原因显示在项目中。旧作品可在作品页点“合并已完结章节”，填写系列名自动查找，或勾选需要的章版本；手动确认表示用户要求合订，不由程序判断文学结尾。相同章节正文重复操作复用相同终稿文件。

### LivingMemory 适配

默认开启 `livingmemory_integration`，在已启用且当前会话允许的插件中优先选择 LivingMemory，未安装则沿用 MemoryCompanion。需要同时重载 LivingMemory 与本插件：本地 LivingMemory 新增 `autonomous_recall` / `autonomous_record` 专用接口。召回遵守 LivingMemory 白名单、记忆作用域及人格过滤设置，不触发普通请求钩子，不记录虚构的用户“自主心跳”。读取超时或未就绪时继续使用近期对话，页面记录失败状态。

实际提交成功的主动文本按 assistant 写入 LivingMemory 对话缓冲，使用 Bot 身份；不是直接创建长期记忆，也不立即触发反思。未发送、沉默、内部计划和工具控制JSON不写入。后续提炼仍遵循 LivingMemory 原有总结流程。此适配依赖本机新增接口，更新覆盖 LivingMemory 后需保留这两项接口。作用域和人格是否跨用户共享遵守 LivingMemory 自身配置。

### 内置网页面板

加载插件后刷新 AstrBot 网页，左侧栏插件页面中会出现 **「我只在乎你」**。页面通过 AstrBot 原生页面发现和登录鉴权桥接加载，无需额外端口。

- **概览**：对象状态、行动中会话、持续项目与待分享数量；立即判断、结束本轮、进入计划。今日用量与免打扰也在这里，工具与技能收在展开项中。
- **计划**：当前任务、持续项目、自主节奏、明确偏好；待办条件、约定、断点与取消记录按需展开。
- **作品**：按类型筛选作品，点开后才加载图片或正文；成果箱发送、重新准备与丢弃，历史保存回执折叠显示。
- **记录**：最近一轮决策、执行契约、行动记录；事实凭据、重复失败与 ComfyUI 检查收在展开项中。
- **设置**：对象、预算、节奏、高级工具与作品目录分组展示，高级项默认折叠。

页面每 15 秒刷新，只有数据变化时才重绘对应页面；滚动、展开状态与未保存编辑不会被定时刷新覆盖。支持明暗主题和窄屏布局，弹窗使用页面内控件以适配 AstrBot iframe 沙箱。

1. 在 AstrBot 插件管理中扫描/重载本插件（或重启 AstrBot）。
2. 在插件配置的 `targets`（对象 QQ 号列表）中直接填写对象 QQ 号并保存，即自动持续启用，重启后仍然有效，无需发送开启命令。只有一个 OneBot 平台时自动识别；多个平台实例时，在 `platform_id` 填写对应实例 ID。也支持管理员在私聊发送 `/自主 开启` 自动绑定。
3. `/自主 预览` 只读取上下文、记忆并给出选择，不执行行动、工具或主动发送。
4. `/自主 立即` 安排一次真实的自主判断，bot 可以选择沉默。
5. `/自主 状态` 查看下次时间、记忆联动和错误；`/自主 关闭` 停止本私聊。

默认总开关开启、目标列表为空；填写 QQ 号即可自动调度。也可在 `targets` 中填写真实 UMO（`/sid` 获取）。需先与 bot 聊过天，有可用的当前会话。插件配置支持间隔、浮动、窗口、轮数、工具预算、模型超时和额外行为提示。

## 行为

- 一次窗口默认 15 分钟、最多 4 轮、总计最多 12 次工具调用。bot 自行选择下一步目标和 30～300 秒后续行；不要求用户回复。
- 支持一个可更新的持久化未来计划：bot 可在主动判断或行动后记下想做的事，下次周期主动自动读取，自主选择执行、延后、修改或取消。沉默时也能记下计划；跨小时、重启、用户回复仍保留，完成后由模型清除。`/自主 状态` 可查看未来计划。计划在本插件 KV 中单独保存，不依赖长期记忆检索是否命中。
- 每轮先判断是否值得行动，再使用 AstrBot 原生工具循环执行；工具返回参与本轮决策，执行摘要和已发送内容参与后续决策。
- 使用当前会话的模型、人格和人格工具选择，过滤停用工具及会话禁用插件，保留工具权限检查。`allowed_tools` 可进一步限定工具名称。
- 现有插件工具及 MCP 工具可用。依赖特定平台事件属性的工具可能不支持合成事件；失败信息交给模型判断。工具中的异步后台副作用不能保证随当前回合取消。
- 用户发来新消息会取消正在运行的旧回合和续行；近期普通模型请求期间推迟主动。不同会话分别调度。
- 真实发送内容作为 assistant 消息追加到原会话，不伪造用户消息；同时通过记忆桥接写入可见时间线。JSON 控制信息、沉默判断不会写成用户对话。
- 状态、待续目标、最近行动记录存放在 AstrBot 插件 KV 中。重启后恢复未来计划；中断中的行动不重放，避免重复副作用。
- 平台返回只表示发送接口已执行，不代表终端已确认送达；失败或不确定发送不自动重试。

“我会牢牢记住你”未安装、停用、超时或拒绝返回记忆时，以近期上下文继续，状态中显示原因。尊重记忆插件现有接口策略，不绕过其检索限制。

## 1.1 自主计划与持续项目

- 普通聊天完成后等待 20 秒整理未来计划、项目和明确偏好。连续发言会取消旧整理任务，减少重复模型调用；可通过 `chat_planning` 关闭。每次整理额外调用一次当前会话模型。
- 最多保留 5 个持续项目，包含目标、实际进展、下一步、作品引用及 active/paused/completed/cancelled 状态；已有项目按 ID 更新，不会因单次主动结束而丢失。完成或取消的项目可被新项目替换。
- 模型可以选择 5～180 分钟后的下次周期判断；未指定时仍使用配置的约一小时检查。短时续行有更高优先级。
- 模型选择 `notify=false` 时，本轮后台推进，不发送最终文本，通过事件发送的工具消息也被阻止。直接绕过事件自行调用平台 API 的第三方工具需由该工具配合，不属于本插件可拦截的发送链路。
- 主动的 tools/create 轮实际调用过工具（如 `autonomous_dsh_task`）但模型没给正文时，`tool_work_message` 按**真实工具回执**补一句自然收尾，不再只留下工具状态气泡就没有下文；工具失败也如实说一句，不静默吞掉。本身就是发消息/发文件的工具（`send_message_to_user`、`autonomous_send_artifact` 等，见 `delivery_tools`）不重复补。chat 轮查完资料想沉默仍可沉默；`notify=false`、免打扰、预算耗尽及用户新消息中断仍优先。
- 保存工具实际返回的简短摘要，供后续主动判断使用。长作品需用可用的文件工具真实保存，项目中只记录返回的位置；短草稿可保存在项目进展中（最多 6000 字符）。
- 偏好来自用户明确表达，并检查证据片段确实存在于用户本轮原话；不从未回复推断喜恶。该检查验证来源，具体语义仍由模型判断。相同主题遵循最新表达，最多保留 12 项。
- `/自主 状态` 显示项目、偏好及事件数量。

### 事件唤醒

默认 `tool_event_wakeup=true`：普通聊天的工具返回进入事件队列；聊天忙碌、最近发言冷却结束后，bot 自行判断是否值得跟进，不直接强制发消息。同一次事件按 ID 去重，成功判断后消费，失败则保留。

其他插件可发现本插件运行实例并调用：

```python
await autonomous_plugin.notify_event(
    target_umo,
    "图片任务已完成，结果位置：实际返回的地址",
    event_id="image-job-唯一任务编号",
    source="image_plugin",
)
```

这里只接收真实结果，不自动订阅新闻、日历或监测第三方后台任务。此类事件需由提供结果的插件调用接口。事件默认约 30 秒后触发判断，仍受普通聊天冷却影响；同会话事件会合并。

## 与其他主动插件配合

### 1.3 可选陪伴适配

`companion_integration` 默认开启。每次主动重新发现「我会永远陪着你」当前有效的公开扩展 API，不导入其模块、不依赖其安装，也不改写对方配置。

- 安装并启用时，通过 `prepare_proactive_chat` 读取当前关系、状态和日程上下文，并申请其主动发送占用。明确拒绝或暂缓时本轮不执行，下一周期再判断。
- 对方关闭主动联动或未管理本对象时，按接口的允许结果继续，实时上下文能力可用时补充状态。
- 行动期间通过外部活动接口通知占用；该插件现有主动闸门能据此暂缓其他主动。结束、沉默、异常和取消时释放本次占用。
- 实际交给平台的内容在本轮结束后同步到对方主动记录和短期连续性；没有发出的内部草稿不会写成已发送消息。多条内容按一个行动回合汇总同步。
- 未安装、停用、会话禁用或接口不可用时，独立运行。接口错误有日志，并在「计划」及 `/自主 状态` 显示降级状态；不覆盖独立计划和项目。
- 预览不申请发送占用、不登记活动、不写入对方发送记录。

这是公开状态与调度接口适配，不是对方完整普通聊天钩子链；双方创作库仍独立。本插件保留自己的工具预算与多轮行动，不强制套用对方仅针对纯文本的终审接口。已进入平台发送阶段的消息无法靠活动占用撤销，因此协调能减少碰撞，不保证所有第三方发送绝对互斥。旧 `proactive_private` 等没有接入协调的独立调度源仍建议关闭重复入口。

## 验证

### 1.10 核心链路收敛与网页重构

持续项目追加修复：选择阶段禁止写入新进展/产物及完成状态，执行受阻不能标完成，存在必要 next_step 时保持进行中。项目更新保留最近8个历史版本；进展超过6000字符拒绝而非截断。同名更新原记录，满5项明确报错、不覆盖已完成项目。网页可编辑字段、查看历史、按项目ID安排推进；暂停清除绑定的临时任务。失败和核验不通过计数并逐步冷却，断点最多连续优先2轮后让出自主判断机会；候选按最近尝试时间排列。这不是严格轮转保证，也不能自动验收任意创作目标。

持续项目补充代码级状态保护：模型不能覆盖或自动恢复 paused/completed/cancelled 项目，网页可明确恢复。断点保存 project_id，关联项目非 active 时不再自动选取；暂停保留断点和草稿，恢复后可继续。删除移除关联断点；用户手动添加同名项目视为明确重建许可。旧记录若缺少项目 ID，只能按已有标题/目标文本关联，不能保证识别任意改写。项目为自主候选，不保证每轮执行；progress 是模型提交的进展，不等于已校验保存的作品文件。

断点增加有界任务索引（20项），同会话未完成任务按最近更新时间轮转，受阻后至少5分钟再尝试；兼容旧单断点。取消匹配移除“同属画图/小说就取消整类”的规则，保留明确文本与严格相似匹配。不是完整语义任务管理器，文字改写仍需用户核对。

契约明确区分 reply/external；无工具外部查询不再自动完成。仅 ok/success 的笼统返回降为 observed，不足以证明实际动作成功。收尾不按整个工具名排除已用工具，具体参数调用仍由去重保护。

成果箱加入时保留本地文件/正文快照，原文件变化不会默默替换待发版本。长同步正文可导出完整txt发送。准备阶段失败标failed，可网页重新准备；提交阶段异常仍为uncertain，不盲重发。远程图片保留引用，未下载前并非内容快照。

作品自动发现/陪伴同步移为后台任务，页面读取缓存不等待同步；停用时取消同步任务。本地图片页面缓存包含修改时间。未接入的第三方后台取消、全格式回执语义验证、所有媒体相册同步及真实浏览器全流程仍不宣称完整支持。

网页重构为五个单一职责页面（概览/计划/作品/记录/设置），状态按内容签名刷新，避免每 15 秒整页重绘；作品图片与正文点开后才读取，图片预览并发上限 2、缓存有界。旧的 `daily-ui.js` 已由 `plans.js`、`library.js` 取代，页面共用 `common.js`。仓库根部遗留的 `pages/我只会陪着你`、`pages/自主陪伴`、`pages/pages` 是历史副本，不属于当前页面，可在确认后删除。

### 通用成果箱

作品库全部类型都可加入成果箱，以 work_id 引用原作品，不再复制正文作为唯一形式。图片通过已登记来源加载为图片消息；脚本、程序包及其他本地文件通过 File 消息发送原文件（20MB上限），不执行代码；短正文直接发送，长正文有原文件时按文件发送，纯同步正文过长时提示先保存文件，不悄悄截断。兼容旧文本成果条目。

网页提供查看原作品、发送、丢弃；相同作品在 pending/sending/sent/uncertain 状态不重复入箱。发送前持久化 sending，成功为 sent（平台提交，不保证终端收到）；发送异常标 uncertain，不自动重发。原作品缺失时不猜路径、不发送替代内容；已分享作品不会自动重新塞入队列。

### 通用文件作品

作品目录不再只接受 ComfyUI：结构化工具的真实成功回执中的 file/path/output_path/image_path、files/artifacts/output_files 可登记本地实际文件；代码执行器 `saved: 绝对路径 字节数` 及实际发送的本地文件也会登记。每次登记校验文件真实存在，按引用去重并更新大小、修改时间。

支持正文、源码/脚本、本地图片、程序包及其他二进制文件。正文和代码仅文本展示，图片按真实文件内容预览；所有已登记本地文件可下载（20MB上限），不会执行脚本或内嵌运行HTML。当前会话/人格作品目录的历史发现不再只筛txt/md。远程图片目前仍只自动读取已配置ComfyUI的view接口；其他远程服务需先通过工具保存本地，避免页面代理任意地址。

### 实际作品目录补录

作品目录统一登记本插件保存工具、safe_write 的实际文件回执、模板 completed 中的真实图片 URL。重载时从已存工具回执、断点、生成产物回填并按引用去重；图片链接是生成引用，不冒充本地下载完成或送达确认。

网页“补录历史文本作品”只检查当前会话人格对应的旧 `astrbot/数据/<人格>/作品` 及本插件当前会话文本目录，不扫描全盘。正文可查看，并手动加入成果箱；只读已登记文件，超过1MB不在页面读取，超过8000字符不截断后冒充整篇分享。已发送作品不自动转为待分享，成果箱表示待处理内容，空箱不代表没有作品。图片当前展示引用与来源，不自动把图片链接作为文本成果发送。

### 节奏与偏好分层管理

自主节奏区分 self（临时自主调整）、global（用户明确的整体联系频率偏好）和 topic（仅限制某类话题，不调全局）。global 需要本轮用户原话证据；取消画图、删除项目不再直接减少所有主动。调整默认有效120分钟，可设10～1440分钟，到期恢复默认并重新评估。网页显示有效期和最近8次变化。旧的“取消画图所以少联系”节奏在加载时纠正。

明确偏好最多12项，记录用户原话、创建和更新时间；网页可删除或固定，最多固定8项。容量淘汰优先保留固定项和近期更新项，同主题新表达会更新值并保留固定状态。固定不等于禁止用户改变偏好，不设自动到期；删除后新的明确表达仍可重新记录。旧记录缺少时间时显示未知，不伪造历史时间。

### 取消记录约束

取消临时任务或删除项目时，保留有界取消记录；规划拒绝相关旧事项重新形成未来任务或项目，执行前也过滤，便签/日程创建和记忆写入工具不得将相关旧任务转存恢复。初始化从已有项目删除标记迁移取消记录，清除匹配的本插件计划与断点。匹配使用文字相似与常见动作类别，属于保守的启发式；重新保存明确手动任务可解除匹配取消记录。网页显示取消事项。

已写进其他插件的便签不由本插件直接改库删除；本插件不会再据此主动恢复相关事项。其他插件自身仍可读取这些便签，需在其便签页面独立删除。无工具的 observed 契约项用于普通文字步骤，不再强求虚构工具回执。

### 跨回合任务断点

执行契约、实际工具回执（含结果引用和任务 ID）、媒体投递记录在调用前后持久化。相同任务、相同会话恢复时，沿用原契约和回执，只提供尚未确认完成的工具；verified/success/pending/attempted 的已调用工具默认不重放，用户批准的只读条件查询工具可继续查原任务。模糊或中断回执保留为待核实，不盲目重交动作。

非手动任务的未完成断点在后续周期继续；手动任务优先。用户回复打断旧回合但保留断点，后续结合新上下文恢复；网页重新保存/清空手动任务时清除旧断点，避免混用目标。网页展示当前断点及每个工具状态。该保守机制以工具名阻止重放，复杂任务需要同一工具处理多个不同对象时可能需重新明确任务，不保证任意第三方任务都有状态查询能力。

### 通用执行契约

默认 `general_execution_contract=true`：执行前额外一次模型规划，将任意任务分为仅回复或实际动作，并建立最多 4 个可核对目标，绑定本轮真实可用工具及 observed/success/completed 要求。无对应工具仍是未完成动作，不改成聊天掩盖。逐项目标核对本轮回执，其他无关工具成功不能替代目标；任务 ID 仅代表处理中，completed 但空产物不能作为产出完成。网页展示执行契约和核验结果。

这仍不是通用现实证明器：目标分类与完成条件由模型规划，工具结构化成功只证明工具自身回执，不能保证任务参数语义完全正确。未知格式保留待核实，不只靠模型自己说完成。普通聊天可直接回复；既有动作关键词作为补充检查而非唯一入口。

### 外部动作落地校验

画图/生成媒体、保存、文件传输等明确动作任务会检查本轮工具回执，而非依赖模型的 completed 自述。完全没有工具调用时允许一次执行纠正，仍只承诺不行动则保留任务、标为未执行，并抑制该轮虚假完成正文；已有工具调用则不重放，避免重复副作用。仅有任务 ID 视为处理中，模板 completed 但 outputs 为空不算完成。网页显示校验状态和原因。

校验只覆盖当前识别到的动作类型和已支持的回执结构，不是所有自然语言与第三方返回格式的通用证明器。无法识别的回执标为待核实，不冒充成功。工具自行直接发送的正文不能事后撤回；代码层校验的是最终回复和任务完成状态。

### 1.8 全链路检查修复

- 预览跳过服务/条件查询和 MCP 重连，不执行登记的只读工具，不改变实际执行阶段；只进行必要的模型判断和上下文读取。
- 模型结果格式修复后重新核对用户消息版本，防止修复期间收到消息后仍提交旧回复；发送前持久化完成后再核对一次版本。
- 工具状态提示保留发送预算统计与日志，不写入普通对话、记忆时间线或陪伴“已说内容”，避免状态提示污染人格连续性。
- 暂停全部行动会递增版本并清除当前窗口；取消收尾尊重新的暂停时间或用户回复后的安排，不覆盖网页刚设的状态。关闭总开关或移除对象也取消计划整理任务。
- 窗口预算豁免需已正式准入，首轮预算校验在递增轮数前完成；窗口外保持每日限制。超时显示明确原因，重启恢复结果立即持久化。
- 模型计划中的可选 null 字段按省略处理。执行输出的计划、频率、成果箱变更先在副本中校验，避免后续字段错误导致部分更新。
- 网页校验频率上下限及实际执行范围，状态标签改为中文，并展示阻碍原因；刷新请求不重叠，配置保存失败返回可读提示。
- 停用/重载时移除属于旧实例的页面接口，避免停用后仍调用旧对象。技能目录保留 AstrBot 的运行环境提示；被权限或预算拒绝的条件查询不伪装成有效观测。

### 模板 MCP 晚启动恢复

配置中的「ComfyUI生图」指向 `/app-mcp`。加载模板生图技能且本轮 ComfyUI 就绪时，若共享工具管理器缺少 `list_templates/get_template/run_template`，插件通过 AstrBot 原生 MCP 生命周期接口重连指定服务，重新注册其工具。重连只针对已配置且未停用的服务，60 秒冷却，不调用生图、不修改 MCP 配置。失效运行实例可能被重建；重连失败在网页显示具体状态，任务保留。最终工具仍受当前人格、工具启用和会话过滤限制。此恢复需要到下一次相关主动回合触发，修改磁盘代码不等于当前进程已重连。

### 已开始的主动窗口预算豁免

`ignore_budget_while_active` 默认开启，并显示在网页每日预算设置里。窗口已有执行回合且尚未过期时，忽略本插件每日判断、回合、工具、消息次数以及窗口工具次数限制，次数继续累计。首轮调度准入仍检查每日预算；窗口到期、对方回复清空窗口或手动停止后恢复预算检查。窗口时长、最多回合、单回合模型步骤、工具/回合超时、暂停及外部插件规则不受该开关影响。

### 生图入口与预算调整

主动回合现已补齐原生技能目录注入，按当前人格、插件启用范围及本地工作区加载，与普通聊天采用相同的 SkillManager 和过滤逻辑。模型应读取任务匹配的已学技能后沿用其指定步骤，不强行改用 pc_generate_photo。每轮在网页记录实际工具和技能目录列表。技能文件仍需模型按需读取，目录加载不等于每个技能已执行。

默认每日预算提高为：判断 144、执行回合 96、工具 300、发送尝试 200；窗口工具 24、单回合模型步骤 12。本次同时更新当前本地配置文件；已有今日计数不清零，需重载配置后采用新上限。

### 1.7 阶段、凭据、停滞与约定

- 网页「计划」显示真实任务阶段、运行编号和最后更新时间。保留真实 Task 的互斥，不因界面心跳过期而重复启动任务。
- 来源凭据最多保留 30 条，区分模型自述、工具返回、校验后的文件保存及平台发送接口返回；不将模型摘要当成保存或送达证明。
- 相同工具和参数返回相同失败三次后，对该调用冷却 15 分钟，不取消原任务。参数变化可换方案，成功返回会清除该调用的失败记录。回合异常也记录失败签名；仅明确错误返回参与工具冷却，不把重复聊天当失败。
- 从普通聊天整理约定时要求用户原话证据与明确时间，最多保留 20 项；保存 pending/resolved/cancelled 状态。用户交代结果后可回填 resolved，网页可手动了结或取消。
- 约定前 1 小时或过后 1 小时到 24 小时提供关心机会，最多每 15 分钟重新判断；仍遵循暂停、预算及会话冷却。只有实际正文提及事件且执行结果登记了对应 ID，才消耗前/后提醒。时间与结果由模型提取，原话匹配只是来源检查，不能保证时间语义绝对正确；网页可核对并取消。
- 不接管「我会永远陪着你」原日历，也不跨对象寻找替代收件人。独立约定记录与原日历可能重叠，需按实际使用关闭重复提醒来源。

### 通用待办条件检查

模型可在计划整理或主动输出中通过 `conditions` 保留最多 3 个真实依赖，后续每轮实际重新查询，结果带时间与变化标记。网页「计划 → 待办条件」可查看结果或编辑条件 JSON；设置中可填写只读查询工具名称及允许检查的文件目录。

支持 HTTP GET 状态接口、TCP 连通性、文件存在/大小/修改时间和用户批准的只读工具。HTTP/TCP 响应只代表观察结果，不等于任务已完成；工具查询需保留原任务 ID 参数。无权限、工具不存在、失败或超时均返回 unknown，不沿用旧结论。工具查询计入调用预算并经过原权限检查，自动条件检查时禁止通过事件发消息；第三方工具本身必须确实为只读，不能仅凭工具名保证无副作用。HTTP 地址也应只使用实际只读查询接口。

示例：`[{"id":"image-job","kind":"http","url":"http://127.0.0.1:8188/history/实际任务ID","label":"原绘图任务"}]`。文件例：`[{"id":"output","kind":"file","path":"D:/output/result.png"}]`，需要先配置允许目录。ComfyUI 专用就绪探测仍保留，作为通用机制的已有适配。

此机制自动复查已登记的条件，不是任意第三方工具的全自动接入；模型需登记真实条件，或用户在网页填入。创作进度使用每轮重新加载的项目及聊天上下文；需要实际文件新版本时应调用对应读取工具，不由元信息推断正文。

### 连续主动中的 ComfyUI 状态刷新

涉及 ComfyUI、补画的任务、最近项目或对话时，每轮执行前真实请求配置地址的 `/system_stats`，超时 5 秒。仅预期 ComfyUI 状态响应标为 ready；连接失败、超时、非预期服务标为 unknown，而不是断言没有开启。最新检查及“ready 后停止催开，尝试原绘图工具”的指令进入本轮上下文。每轮重新检查，不把旧结果缓存为当前事实。

网页设置可调整 `comfyui_url`（默认 `http://127.0.0.1:8188`）及关闭探测，「计划」显示最近实际检查时间与结果。此探测不代表绘图工作流一定可用，也不直接执行绘图；实际绘图仍由模型选择已启用工具。不是持续后台监控：用户在两轮之间启动服务，会在下一次相关回合发现。

### QQ 工具可见性与回复中断

`show_tool_calls` 默认开启，主动工具执行前和返回后在 QQ 显示工具名称及简短状态，不输出参数及原始返回。通知计入每日发送尝试预算；后台模式、免打扰及预算耗尽时不发通知。返回结果不等于 QQ 已确认收到动作。

主动事件为 OneBot 平台接入真实 `get_client()` 客户端，支持依赖 `event.bot` 的戳一戳工具。本地 pokepro 的主动严格路径会传回真实调用异常，不再吞异常后报告成功。更新后需重载 pokepro 和本插件。

真实对方私聊发言会提前取消旧回合、清除短时续行，并重排下次周期；已发出的消息或已提交平台的动作无法撤回。未来手动任务仍保留供后续周期处理，不会立即重复启动旧连续窗口。

### 作品真实保存

主动 Agent 内置 `autonomous_save_work` 工具，传完整正文后写入 `data/plugin_data/astrbot_plugin_autonomous_companion/works/<会话哈希>/` 下的 UTF-8 文本，读回校验后才返回保存回执。网页「计划」显示已核实的作品标题、字符数和路径，并单独显示可选陪伴作品库同步结果。旧行动摘要仅为模型报告，不能凭摘要恢复缺失正文。

启用陪伴适配后，保存工具还会调用陪伴插件新增加的 `import_completed_text_work` 接口，将完整正文导入当前事件人格的 `creative_projects`，作为已完成作品，可在陪伴作品目录及正文读取工具中找到。导入按来源及正文摘要去重，遵守对方现有创作写入权迁移限制，并等待持久化队列完成。首次需要重载两个插件；接口不可用、写入受限或失败时保留本地文件，网页回执显示未同步原因，不假报成功。此功能只同步新调用保存工具的作品，不根据旧摘要伪造正文。

### 1.6 自主主动频率

- 默认允许模型以 `rhythm_minutes` 和 `rhythm_reason` 为每个对象持续调整基础检查间隔，范围默认 10～180 分钟。不同对象独立保存，重启和用户回复后仍沿用。
- 普通聊天后的计划整理、主动判断及行动完成时均可调整。判断次数不等于发送次数，模型仍可沉默。
- 网页「设置 → 节奏与自主性」可关闭自主调整或修改上下限；「计划 → 她的主动节奏」显示间隔、原因、更新时间、下次判断，支持恢复默认基础节奏。
- 单次 `next_check_minutes`、事件唤醒、短时续行仍有各自的调度优先级；暂停和每日预算仍生效。恢复默认不会删除计划和项目，也不关闭模型未来再次调整的能力。

### 1.5 成果箱、免打扰与每日预算

「计划」选择对象后：

- **今日使用量与免打扰**：查看当天判断、执行回合、工具、发送尝试及失败数；支持暂停全部 1 小时、仅暂停发消息 1 小时、自定义暂停分钟和立即恢复。最多暂停 7 天，到期自动恢复。仅暂停消息时仍可后台工作，成果文本可暂存。
- **稍后分享 · 成果箱**：模型可保存已完成的文本、作品引用与暂不分享原因。最多保留 20 项；可展开查看、手动发送文本或丢弃。重复文本去重，发送前持久化状态；发送异常或重启时中断的发送标为“待确认”，不自动重发。图片/音频位置只作引用，此版不读取文件、不提供媒体预览或自动上传。待分享成果由用户手动处理，模型不重复主动发送同一份内容。
- 网页「设置 → 每日预算」默认每对象每天自动判断 48 次、执行 24 回合、工具 60 次、发送尝试 20 次；0 表示该项不限。自动判断或执行回合耗尽后等到主机本地次日零点恢复；消息上限耗尽可继续后台工作；工具上限逐次拦截。
- 计数是本插件的判断/执行回合及调用次数，不是所有 LLM 请求或精确费用；单个 Agent 回合可能包含多次模型请求。手动预览、普通聊天计划整理另计次数，不扣自动判断限额。这里不提供 Token/金额估算。
- 发送计数包括模型、工具通过本插件事件发出的消息及手动成果发送；第三方绕过事件直接调用平台 API 的行为不纳入统计。暂停同样只影响本插件，不改变其他插件的独立发送开关。

### 1.4 自检与执行透明度

- 「运行概览 → 开始自检」只读检查平台、会话、人格和模型配置，不执行模型请求。记忆、陪伴状态明确显示为上次读取结果，不将配置存在当作调用成功。
- 「计划」可以手动添加/删除项目、预览一次真实模型判断；预览不执行工具也不发消息。
- 「行动记录」新增最近一轮的触发来源、目标、简短依据、结果、失败与未发送原因。
- 项目保存最后进展时间；模型通过 `project_id` 关联的回合失败时累计失败次数，实际进展更新后清零。未关联项目的错误不猜测归属。
- 陪伴接口返回已知的休息、安静时段或消息预算限制时，允许仅后台行动；其他明确拒绝（含并发、边界、未知原因）仍暂缓整轮。后台发送限制依然只覆盖本插件的事件发送链路。
